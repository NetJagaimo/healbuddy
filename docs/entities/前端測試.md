# 前端測試

## 決策
每一項功能都要有自動化測試，確保操作正確；測試未通過不得部署。

## 原因
確保每個操作（新增品項、記錄攝取、打卡運動、統計紀錄）都正確，且之後修改不會悄悄壞掉。

## 範圍與限制
- **單元測試**（Vitest）：胖胖等級計算、週 / 月統計、日期切換（含午夜邊界）、資料存取層。
- **元件測試**（Vitest + @testing-library/svelte）：按鈕、表單、清單的互動。
- **端對端測試**（Playwright，手機尺寸 viewport）：完整使用流程、重新整理後資料仍在、離線模式可操作。
- 新功能的定義：「完成」= 功能 + 對應測試 + CI 通過。

## 對實作的影響
- 儲存層要可注入 / 可替換（測試用 fake-indexeddb）。
- 元素加上可讀的 role / label，方便測試以使用者視角選取，也順便提升無障礙。
- CI（GitHub Actions）在每次 push / PR 執行全部測試，是 [[github.io架站]] 部署的前置步驟。
- E2E 以固定時間（2026-09-26 15:20）與 `Asia/Taipei` 時區執行，確保日期相關結果穩定。
- 需要等資料寫入完成的步驟（例如重新整理前），以「已記錄」提示出現為準——提示在寫入完成後才顯示。
